Fix 2 — Server-side render your services page

Make prices exist in the HTML before JavaScript runs

Fix 1 is a band-aid — it gives AI a structured-data copy of your prices. The root cause is that your /services page renders prices with JavaScript. Copilot and Google read the raw HTML, where your prices literally don't exist yet.

Your site runs Next.js, which supports server-side rendering out of the box. Ask your developer to switch /services from client-side rendering to getStaticProps (static generation) or getServerSideProps (SSR). This makes prices appear in the HTML that every crawler — including Copilot — receives.

Next.js — services page 
// In your /services page component (e.g. pages/services.tsx):
// Change from client-side data fetching to static generation.
// This makes prices appear in the HTML at build time.

export async function getStaticProps() {
  // Fetch your services data from your CMS or data source
  const services = await fetchServices();
  return {
    props: { services },
    revalidate: 3600  // rebuild every hour
  };
}

// Your component then receives services as a prop
// instead of fetching them in useEffect/useState.
// The HTML now contains every price before any JS runs.
